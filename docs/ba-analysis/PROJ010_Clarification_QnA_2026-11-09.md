## S. Stack, hosting and budget (MASTER_PLAN A6; R2SS Q043, Q050-Q054, Q109)

### What the 11 Must use cases need from a stack

| Need | From |
|---|---|
| Google sign-in and an emailed one-time sign-in link, for customers; Google sign-in from an allowed list for admins and staff | UC08 AC01, UC12 AC01 |
| A server that alone decides each game's result and writes points, once per ticket; holds the memory-card layout | UC09 AC04-05, UC03 AC05 |
| A database with roles: a customer sees only their own data, staff only first name and reward, admins everything | UC12 AC02-03, UC06 |

| $0 running cost on free plans | CLAUDE.md, Q043 |

### The proposal

| Layer | Proposed | Why | Free-plan limit that matters |
|---|---|---|---|
| Front end | **Vite + TypeScript**, small screens in **Preact**; the games in plain **Canvas 2D**; bottle flip with **Matter.js** (free, open source) | Small download for phones; no heavy framework (Q011) | - |
| Hosting of the pages | **Cloudflare Pages** (free) | Unlimited bandwidth on the free plan; allows a business site (to confirm in its terms *(check)*) | 500 builds a month; 20,000 files per deployment |
| Database, sign-in, files | **Supabase** (free): Postgres, its sign-in service (Google + email link), file storage | One free service covers the database, sign-in and roles; the server-side game rules run inside the database as functions, so there is no separate server to run | 500 MB database; 1 GB files; 5 GB egress a month (one source says 10 GB) *(check)*; 50,000 monthly active users *(check)*; 2 free projects; paused after 7 days without traffic |
| Emails for the sign-in link | A free email service through Supabase's custom email setting: **Brevo** (300 emails a day) | Supabase's built-in sender sends 2 emails an hour and is not for real use *(official)*; Brevo's daily allowance covers a launch night; Resend's free plan is 100 a day | 300 a day *(check)* |
| Tests | Vitest (logic), Playwright on a phone-sized screen (pages), the database functions tested against a throw-away Postgres in GitHub Actions | All free; Playwright is already installed in cloud sessions | - |
| QR code | Generated by a committed script as an image | Free; no QR service | - |

**Not proposed:**
- **Vercel's free plan** is limited to non-commercial personal use *(official)*. Deckbar is a business.
- **Firebase's free plan** cannot run server functions. Those need its pay-as-you-go plan with a card on file.
- **A server of our own** (a VPS, a container) would be more to run and secure, against Q011.

### Will 10,000 customers fit on the free plans?

| Limit | Estimate at 10,000 registered customers | Fits? |
|---|---|---|
| Database 500 MB | Customers and consents about 10 MB. Games: if 2,000 customers are active and play 12 games a month, about 24,000 games a month, about 5-10 MB a month. Worst case (all 10,000 active): about 50 MB a month | Yes, **if** the detail of old games is trimmed (S6) |
| Egress 5 GB a month | A game is about 20-40 small requests (memory card: one per tap), about 30 KB. 24,000 games is about 0.7 GB. Worst case about 3.6 GB. Reward images are resized on upload to about 100 KB, or they eat the allowance | Yes for the realistic case. The worst case is close to the limit |
| 50,000 monthly active users | At most 10,000 | Yes |
| Pausing after 7 days without traffic | Production has traffic every night. Dev may pause; it is resumed by hand | Yes |
| Email 300 a day | Google sign-in sends no email. An email-link sign-in sends one, and stays signed in for 90 days | Yes, unless more than about 300 people register by email on one day |

The printed QR code also cannot change later (A18) | (a) **If Deckbar has a website domain:** a sub-address such as `games.` + Deckbar's domain, and the sign-in emails sent from it. $0, but someone at Deckbar must add 3-4 DNS records. (b) If not: buy a domain, about USD 10-20 a year *(check)*. (c) Not recommended: send from a Gmail address through Brevo; such emails often land in spam. Your answer: does Deckbar have a domain? | Q054 |
| S10 | Where do the server rules live? | Inside the Supabase database as functions, with row-level security for every table. Customers' browsers can only call those functions; no table is open to them directly | Q052 |
